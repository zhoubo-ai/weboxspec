## 主持流程

1. 从未登录首页开始计时，要求参与者注册、选菜、完成一次合法订餐；允许自行查看界面。出现Pending订单详情时停止计时。请其口头说明配送日期、午餐/晚餐、配送地址与订单状态。记录四项原始回答、计时及是否得到帮助。SC-001要求至少9/10在300秒内完成且正确理解配送信息；超时、放弃、得到代操作都保留在10人分母中。
2. 让参与者在设置中选择一种过敏原和一个预算范围，尝试包含该过敏原的配置及超过预算的组合。分别问“这个提示意味着什么？继续操作会怎样？”。记录原话；理解过敏原风险与预算提醒、知道仍须自己决定才算通过。SC-008要求至少9/10同时理解两类警告，不以点击确认本身判定理解。
3. 让参与者输入自己的餐食偏好，获取一次真实AI推荐，查看卡片理由并可选择菜品。记录提示词的非敏感摘要、实际推荐菜名、原样理由及请求ID，询问“这些理由是否与刚才的需求相关？为什么？”。保留不相关、无卡和错误结果；不得反复请求直到满意再挑选记录。SC-010要求至少8/10认为理由相关。若确有预期澄清，记录澄清和后续输入，不能隐去首次结果。
4. 另给一位具备Admin账号的实际运营参与者任务：“新增一款英文菜品，上传本地图片，安排指定日期供应，将它下架，再上架”。从任务宣读完毕到员工菜单可看到上架菜品计时，要求300秒以内。记录操作完成情况、员工页面验证与帮助情况，对应SC-007。
