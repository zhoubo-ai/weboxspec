## 完整范围与模块约束

- **Tier 1 + Tier 2 + Tier 3**：三层全部纳入本次交付；实时库存、AI 推荐和经营看板不再是加分选做项。P1/P2/P3 仅安排实施顺序，FR-001–047 与 SC-001–011 全部必须验收。
- **AI 推荐（必交付）**：必须实际接入可运行的 LLM 服务，自备服务凭据或本地模型；现场不提供 API Key。不得用固定文案、静态结果或虚构成功替代实际功能。
- **库存与实时同步（必交付）**：必须验证同时下单不超卖、提交时复核库存、取消恢复与实时展示；下单不通不能宣称完成依赖下单的库存能力。
- **经营看板（必交付）**：数据必须来自真实订单，可自动或手动刷新，不接受与真实交易无关的演示统计。
- **推荐和看板的依赖**：售罄排除、库存预警需要正确的库存记录；规划须覆盖库存、实时同步、AI 推荐和看板的完整衔接及一致性，具体依赖见规格 A-009。
- **岗位评分**：前端与后端岗位考察侧重不同，但完整前后端、JDK 17 + Spring Boot + 独立 MySQL、原始 AI 对话和订单正确性的底线相同。不得根据岗位差异删减这些交付要求。
