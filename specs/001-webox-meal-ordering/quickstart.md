## 1. 环境与交付前提

准备 JDK 17、Node 24 LTS 与 npm、支持 Compose v2 的 Docker 环境，以及可用的 OpenRouter API 凭据。后端使用项目内 Maven Wrapper 3.9 系列，不要求全局 Maven。前端为 Vite 8，后端为 Spring Boot 4.1.1。MySQL 8.4 必须作为独立服务真实运行；测试也使用独立 MySQL Testcontainers，不能替换为 H2 或其他内存数据库。

需要能下载锁定依赖、MySQL 镜像、Playwright 浏览器，并可访问 OpenRouter HTTPS API。记录 JDK/Node/Docker/浏览器版本、客户端硬件、配置及实际返回的模型/provider/generation ID、暖机和并发。上游硬件与模型 digest 不可得时如实注明；性能必须实测。

实施后仓库应提供以下入口：

| 入口 | 用途 |
| --- | --- |
| `.env.example` | 环境变量模板，仅含示例，不含真实凭据 |
| `infra/compose.yaml` | 仅启动名为 `mysql` 的独立 MySQL 8.4 服务，使用命名持久卷 |
| `backend/mvnw`、`backend/pom.xml` | 后端启动、迁移、种子及测试入口 |
| `frontend/package-lock.json`、`frontend/package.json` | 可重复安装与前端脚本 |
| `.local/media/` 或 `MEDIA_ROOT` 指定目录 | 后端上传媒体的持久目录，重启不清空 |
| `README.md` | 从零配置、API、架构、实际测试报告及原始对话导出位置 |
| `ai-conversations/` | 工具原生导出的完整 AI 编程对话；若另存，README 明确路径 |

## 2. 配置并加载环境变量

以下命令从仓库根目录执行；新终端也先进入根目录。首次运行复制模板，再编辑 `.env`；已有 `.env` 时保留现有配置。

```bash
test -e .env || cp .env.example .env
chmod 600 .env
```

`.env` 使用可由 shell 加载的赋值语法，密码值正确加引号。模板至少包含以下变量：

| 变量 | 本地约定或要求 |
| --- | --- |
| `MYSQL_ROOT_PASSWORD` | 由操作者设置的非空数据库管理员密码 |
| `MYSQL_DATABASE` | `webox` |
| `MYSQL_USER` | `webox` |
| `MYSQL_PASSWORD` | 由操作者设置的非空应用数据库密码 |
| `DB_URL` | `jdbc:mysql://127.0.0.1:3306/webox`；数据库名须与上项一致 |
| `DB_USERNAME` | 与 `MYSQL_USER` 一致 |
| `DB_PASSWORD` | 与 `MYSQL_PASSWORD` 一致 |
| `ADMIN_EMAIL` | 本地预置管理员邮箱，公开注册不会授予此角色 |
| `ADMIN_INITIAL_PASSWORD` | 符合业务密码规则的初始密码；已存在管理员不得被每次种子执行重置 |
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1`，由后端调用 |
| `OPENROUTER_MODEL` | `openai/gpt-4.1-mini`，可显式替换为支持结构化输出的模型 |
| `OPENROUTER_API_KEY` | 仅服务端秘密配置；模板留空，不打印、不提交、不传给前端 |
| `AI_MAX_OUTPUT_TOKENS` | 默认512；两阶段总20秒deadline保持不变 |
| `MEDIA_ROOT` | 可写的本机绝对持久目录；模板可使用 `"${PWD}/.local/media"`，前提是在仓库根目录加载 |

编辑完成后加载；不要把含凭据的完整环境输出复制到报告：

```bash
set -a
source .env
set +a
mkdir -p "$MEDIA_ROOT"
```

后续启动后端、种子或测试的新终端都执行上述加载步骤。`.env`、运行时上传文件、数据库卷、模型文件和测试会话凭据不提交为源码；`.env.example`、依赖锁文件及 `backend/src/main/resources/seed/` 下的 `menu.json`、九道菜所需 `images/` 素材和 `ATTRIBUTION.md` 随源码交付。检查忽略规则未排除种子图片，在干净副本中无需访问原始 Downloads 路径即可加载种子。

## 3. 启动独立 MySQL 与真实模型

在已加载 `.env` 的仓库根目录终端中启动 MySQL：

```bash
docker compose --env-file .env -f infra/compose.yaml up -d mysql
docker compose --env-file .env -f infra/compose.yaml ps
```

等待 `mysql` healthcheck 就绪。首次初始化的库、用户和密码由 Compose 环境配置创建，数据写入命名卷；修改 `.env` 不会自动修改已有数据库用户密码。Flyway 迁移由后端自动执行。

在仓库根目录加载 `.env` 后，验证配置的 OpenRouter 模型：

```bash
./scripts/backend.sh -Pllm-live verify
```

T005 的入口先检查凭据，并执行非流式/流式结构化生成探针；缺凭据或调用失败会使测试失败，不跳过。T116 随业务实现扩展真实推荐用例。生成证据位于 `backend/target/failsafe-live-reports/`，不含密钥和私人提示词。两次小探针不代表推荐功能或时延验收通过；托管模型性能需按固定样本单独验证。OpenRouter 无本地模型下载、`keep_alive` 或本机显存配置。

## 4. 初始化数据并启动应用

### 4.1 种子初始化

在根目录加载 `.env` 后运行单次 seed profile：

```bash
cd backend
./mvnw spring-boot:run -Dspring-boot.run.profiles=seed -Dspring-boot.run.arguments=--spring.main.web-application-type=none
```

预期：自动迁移成功；进程完成后以状态码 0 退出；按 `Asia/Shanghai` 的服务器今天和明天幂等初始化 9 个 PRD 英文样例及配置、管理员、菜单和供应；首次今天及明天各安排九道、每道总量 20 份。仅补缺失菜单，不覆盖管理员后续编辑、不重置已有库存、不生成虚构收入。再执行一次，已有订单、供应占用和管理员密码不变。原始图片已定位：`/Users/zhoubo/Downloads/WeBox-PRD-候选人交付包/webox_product_images.zip`，包含 20 张图且压缩包完整性检查通过。逐张核对后发现原包未提供九道样例的准确对应照片，已按DEC-R08补充生成九张插图；提示词和摘要见项目内 `seed/ATTRIBUTION.md`，菜品字段来自原PRD §6。部署与 seed 不依赖开发机 Downloads 路径。已有日期菜单（包括空菜单）整体保留；只初始化缺失日期。

### 4.2 后端

新终端从仓库根目录加载 `.env`，再运行：

```bash
cd backend
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

默认监听 8080，数据库迁移自动执行。在其他终端检查：

```bash
curl --fail http://localhost:8080/api/v1/health
curl --fail http://localhost:8080/api/v1/auth/csrf
```

预期健康响应为 `{"status":"UP"}`，表示应用与数据库可用；它不证明 AI 服务正常。CSRF 响应具有 `token` 和 `headerName: "X-XSRF-TOKEN"`。这些只读命令只检查入口；需要保留同一会话 Cookie 才能在写请求中正确使用其 CSRF token。

### 4.3 前端

新终端从仓库根目录执行：

```bash
cd frontend
npm ci
npm run dev
```

打开 `http://localhost:5173`。Vite 将 `/api` 和 `/media` 代理到后端 8080，员工从同一前端来源使用 Cookie 会话；不在浏览器保存管理员密码、模型凭据或长期身份 token。开发代理与正式代理均须保持流式响应即时传输。

先注册新员工，再登录：`POST /api/v1/auth/register` 成功不自动建立登录身份，`POST /api/v1/auth/login` 才建立会话；这些写请求均携带 CSRF token，登录/退出后重新获取 token。管理员使用预置账号。界面、表单错误、图表说明、样例菜品和 AI 理由均应为英文。

## 7. 实时库存、AI、看板与持久化

### 7.1 库存流

用两个独立浏览器 context 登录两名员工并打开同一天菜单。A 下单、取消，管理员调整供应，B 不手动刷新即可看到绝对剩余量；1–3 显示 Low Stock，0 显示 Sold Out 并禁用加购。按 [流契约](contracts/streaming.md) 记录事务提交到 DOM 数量更新的耗时。

验证以下竞争和恢复条件：

- 先建立流并缓冲，再获取菜单，将 HTTP snapshot 与流事件按供应行 version 合并；人为延迟旧 HTTP 响应，不能覆盖更高版本库存。
- 重复/乱序事件仅应用较新行版本；更换日期后旧请求和旧流不能改写当前菜单。
- B 断网期间 A 下单，B 恢复后接收全量权威快照并校准；`Last-Event-ID` 不是完整恢复证明。
- 应用在事务提交后、outbox 发布前退出，重启后未发布记录继续发送；重复投递不会重复加减数量。
- 重复取消、重复提交只改变一次库存；会话退出或失效后不继续保持有效订阅；生产代理部署也验证首条数据即时到达和心跳。

### 7.2 真实 AI 与失败恢复

至少准备 20 组包含个人过敏原、售罄、无历史、有历史、明确日期排重、预算和菜系/辣度诉求的功能输入；加入无安全候选、全部近期已点、提示词企图越过过滤的样本。运行前登记每组预期为 COMPLETE、NO_MATCH 或澄清，有候选且预期推荐的用例通过真实 OpenRouter 验证；确定性空候选可不调用模型：

- 100% 推荐指向目标日期真实可售且不含本人标记过敏原的菜品；返回卡片前再次校验。AI 卡片由真实菜单生成，能继续配置和加购并受 5 份规则约束。
- 默认近 7 天为软降优先级，明确排重按指定日期硬排除；候选不足说明原因，不放宽过敏原限制。
- 卡片在完整 item 校验通过后逐步出现，只有有效完整结果和模型 `finish_reason:stop` 和 `[DONE]` 才显示完成；模型不能自行提供可购买商品的名称、价格或虚构 ID。
- 注入截断 JSON、错误 dishId、模型断流、20 秒超时和繁忙队列：英文错误清晰，部分已发卡片标为 partial，不能假报成功；用户可回到普通菜单继续真实订餐。
- 向 provider 注入连接失败后，推荐失败但注册、菜单、购物车和下单仍可用；恢复真实 provider 后能重试。模型收到的内容不含邮箱、地址、密码或其他用户资料。

模型 stub 仅用于可重复故障注入。性能另行预登记至少 20 次有有效候选、预期 COMPLETE 的正常请求；可复用功能输入，但性能样本量独立满足下限，预期 NO_MATCH、澄清与故障用例不在此组。固定合法日期/餐次、稳定供应与偏好、真实模型的客户端环境/模型与provider标识/暖机/并发及请求顺序，避免测试中有意变更候选。

`llm-live` 与浏览器共同按 [流契约 3.4](contracts/streaming.md#34-时限取消与容量) 留证：从浏览器发起请求计首张有效卡片呈现与合法 COMPLETE 显示完成的耗时，服务端耗时另列。固定分母 N 包含全部预登记尝试，缺首卡或未 COMPLETE 的对应耗时记为正无穷，p95 取升序第 `ceil(0.95 × N)` 个值。非预期 NO_MATCH、超时、错误、断流与取消不得事后剔除；部分卡片后失败的完成耗时仍记为正无穷，重试不替换原样本。记录各尝试、失败数与原因，即使 p95 达标，非预期功能失败也须保留为失败。预期无卡/故障组单列终止结果、恢复行为和终止耗时，不填零秒首卡。

### 7.3 看板固定样本核算

建立连续 7 个运营自然日、四种订单状态、午晚餐、含加料和多配置的固定样本，至少留一个零订单日期。固定测试 Clock 的运营今天为 T，选择 D ≠ T，并为两个查询日设置可区分的订单与库存。分别请求省略 `date` 的默认看板及 `?date=D`，独立人工表按各自配送日期核算，并与图表及数据表逐项比对：

- 订单总数和餐次分布计全部状态；待处理数为 Pending + Confirmed。
- 收入及菜品销量仅计 Completed，使用订单历史快照金额；取消不计收入/销量，同菜品不同配置合并份数。
- 概览、Top 10、午晚餐和预警全部使用同一个查询日；默认取 T，显式日期取 D。Top 10 按销量降序，同销量按菜品 ID 升序；不足 10 种只显示实际条目，趋势准确覆盖该查询日及前六日，包括零值日期。
- 库存预警仅含查询日已安排且上架、当前 remaining 为 0–3 的菜品，区分 Sold Out / Low Stock；即使查询历史日也读取该供应行当前状态，不按历史时点重建。
- 响应 `date` 回显实际查询日，`generatedAt` 为当前 UTC 生成时间；有效过去/未来日期可查询，无订单日返回零值，非法日历日期返回 400，不能静默改用今天。
- 新增订单、确认、取消及库存调整后点击 Refresh，3 秒内出现查询范围内已提交的真实变化；英文口径说明、查询日期与更新时间可见。

至少一个样本先改菜名/价格再查历史，确认统计金额不因当前菜单价格变化。不要仅将响应与同一统计实现的输出相互比较。
