# US2 每日菜单与购物车验证

日期：2026-10-16。T029–T044 已完成。自动化执行者：Codex。环境沿用[环境记录](environment.md)：JDK17、Spring Boot4.1.1、MySQL8.4.11 临时容器、Node24、React19.2，三浏览器与375/768/1440视口。

## 实现与数据

V004–V006 建立受控媒体、菜品及选项过敏原、每日菜单和共享供应。菜单仅返回上架且按日期安排的菜品，售罄仍可见。分类取并集，与名称/描述关键词取交集；转义 LIKE 通配符，限制50码点，默认24条/最多100条，按名称和UUID稳定分页。不存在的日期返回400，未创建菜单日期返回空页且不写库。

菜单资料缓存以dishId/version为键，最多10000项、写入后5分钟过期。当前成员、剩余量、库存版本和菜单revision每次查库；整个组装过程使用只读REPEATABLE READ。SQL并发夹具证明：旧事务看到旧根和旧子表、只写旧缓存键，新请求仍得到新版本。提供提交后失效、命中/未命中/逐出指标；业务管理员编辑及旧报价成交拒绝留到US3/US6补测。

购物车统一配置排序去重、必选与单选校验、相同配置归并、按菜品汇总库存、所有增加入口总量不超过5。整数分用安全整数/BigInt检查，保留精确扣除已提交份数的接口。已确认身份后才读取 `webox.cart.v1:<userId>`，仅白名单保存非敏感快照；退出清页面并保留草稿。恢复、换日期及重新聚焦会核对最新菜单，变价待确认，下架/失效配置保留并禁止结算，网络失败提供重试。

菜单具备日期、200ms搜索防抖与旧请求取消、六菜系筛选、分页、空态及错误重试。菜品弹窗显示资料、基础和选项过敏原、配置及实时单价，使用原生dialog并显式把焦点恢复到触发按钮。移动端单列、平板双列、桌面三列；375与1440截图已人工目视检查，无横向溢出。

测试图片由本地资源解码、重编码并登记为真实媒体，不使用远程占位图。汉堡、意面使用内置imagegen生成，原始提示与来源见[素材记录](../../backend/src/main/resources/seed/ATTRIBUTION.md)；沙拉来自用户图片包。当前为隔离测试夹具，正式九菜种子仍归T089。
