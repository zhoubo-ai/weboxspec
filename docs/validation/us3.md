# US3 报价、地址、下单与订单验证

日期：2026-10-16。T045–T062完成。执行者：Codex。使用真实MySQL8.4.11隔离容器、JDK17、Spring Boot4.1.1及三浏览器×三视口，沿用[环境记录](environment.md)。

## 实现

V007–V010创建地址、五分钟报价、订单和不可变条目快照。地址按用户/原文二进制唯一，只有订单成功事务才保存或更新最近使用时间。订单保留原quote UUID，但不依赖quote行存活；成功key与订单同生命周期，取消、完成或清理旧quote后仍能重放。

报价先在只读REPEATABLE READ中校验日期、配置、版本与真实库存，按菜品/规范化配置归并，算基础及所选选项过敏原并集与整数分价格，再短事务保存。报价不占库存。

订单写事务使用READ COMMITTED，按user→quote→升序dish→升序supply锁定，锁后再次判断到期及截单。订单、条目、地址、库存、quote消费和outbox原子提交；条件更新和唯一约束兜底。成功key/hash优先于报价、地址和时段检查；唯一冲突完整回滚后在新事务解析。锁失败最多重试整个事务三次，仍失败返回503可重试，保留原key。

Pending可取消一次，重复取消不变更时间/版本/库存/事件。Confirmed→Completed保留库存占用但释放有效餐次；管理员状态服务已实现并用真实数据库验证，管理员HTTP与界面仍属US6。

前端完成日期/餐次、历史或新地址、服务端报价、过期与改价恢复、订单历史分页/过滤/详情、取消。冻结提交保存在当前账号的内存上下文，不写localStorage；网络结果未知时只能复用原key/payload，跨页面仍保留。短暂会话检查失败隐藏操作但不丢掉冻结请求；只有成功响应才按配置扣除本次份数，保留等待期间新增的份数。用户原文以React文本节点显示。
